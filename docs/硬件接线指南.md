# 硬件接线指南

## 1. 项目目标

本项目基于 ESP32 与 PN532 NFC 模块实现一个简洁的智能门禁系统。系统支持通过授权卡片或物理按钮解锁，并在门关闭并保持 2 秒后执行自动上锁。

## 2. 硬件组成

- ESP32 DevKit V1
- PN532 NFC 模块（HSU / UART 模式）
- 光耦隔离继电器模块
- 电磁锁
- 门磁传感器 / 干簧管
- 6x6x5 微动按钮

## 3. 引脚定义

| 功能 | ESP32 引脚 | 说明 |
| --- | --- | --- |
| 继电器控制 | GPIO13 | 当前固件逻辑：HIGH = 开锁，LOW = 上锁 |
| 内部按钮 | GPIO4 | 按下时为 LOW |
| 门磁传感器 | GPIO27 | 关门时为 HIGH，开门时为 LOW |
| PN532 TXD | GPIO16 | 连接到 ESP32 的 RX 引脚 |
| PN532 RXD | GPIO17 | 连接到 ESP32 的 TX 引脚 |

## 4. 接线说明

### 4.1 PN532 与 ESP32

- PN532 的 TXD 连接到 ESP32 的 RX 引脚。
- PN532 的 RXD 连接到 ESP32 的 TX 引脚。
- TX/RX 线需要交叉连接。
- 该项目当前使用 HSU / UART 模式。

### 4.2 继电器与电磁锁

- 继电器模块建议使用独立 5V 电源供电。
- 电磁锁建议使用独立 12V 电源。
- 继电器触发端与 ESP32 控制脚连接。
- 由于电磁锁为高电流负载，请注意接线牢固并尽量减少线长。

### 4.3 按钮与门磁

- 按钮接到 GPIO4，按下时形成低电平。
- 门磁传感器接到 GPIO27。
- 当前固件已经对门磁信号加入 100ms 消抖逻辑，能够降低抖动误判。

## 5. 软件结构说明

当前固件已经按模块化方式组织，逻辑更清晰，便于后续扩展：

- [src/main.cpp](src/main.cpp)：主流程入口，负责调度按键、NFC、门磁和锁状态。
- [src/hardware](src/hardware)：封装按钮、继电器、门磁、NFC 和日志等硬件抽象。
- [src/logic](src/logic)：包含门锁状态机和授权控制逻辑。
- [src/config.h](src/config.h)：集中管理引脚、延时和授权卡 UID。

## 6. 供电与安全注意事项

- 控制电路与执行电路建议分开供电。
- 电磁锁属于高负载设备，建议不要直接由 ESP32 的 3.3V 引脚供电。
- 如继电器动作与预期相反，可根据实际模块极性调整代码中的高低电平逻辑。

## 7. ⚠️ 烧录注意事项：PN532 串口冲突

**问题：** 如果 PN532 连接在 GPIO16/17（ESP32 的 UART0），烧录时会报错：
```
A fatal error occurred: Failed to connect to ESP32: Download mode successfully detected,
but getting no sync reply: The serial TX path seems to be down.
```

**原因：** GPIO16（RX）和 GPIO17（TX）是 ESP32 的 USB 串口（UART0）。PN532 连接在这些引脚上会干扰烧录器通过 UART0 与 ESP32 的通信。

**解决方案：**

- **方案 A（推荐，一劳永逸）：** 将 PN532 换到 UART2 引脚（GPIO18/19），在 `config.h` 中修改：
  ```cpp
  #define PN532_RX_PIN  18
  #define PN532_TX_PIN  19
  ```

- **方案 B（临时）：** 烧录前拔掉 PN532 的 TX/RX 线，烧录完成后再插回。

## 8. 常见问题

- 如果 NFC 无法识别，优先检查 PN532 的 HSU 模式和 TX/RX 交叉接线。
- 如果授权失败，请确认主程序中的 UID 已替换为真实卡片 UID。
- 如果门锁状态与实际相反，优先检查继电器模块极性和接线方向。
